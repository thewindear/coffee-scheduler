## ADDED Requirements

### Requirement: 跨网络服务身份与授权

平台 SHALL 允许管理员通过受控 CLI 创建服务身份、签发、轮换和吊销凭证、授予操作权限。对外任务 HTTP 接口 SHALL 经 HTTPS 校验调用主体和操作范围，校验覆盖普通队列、按任务类型提交、批量提交、领取、续租、回执、查询和重试。

#### Scenario: 首次接入和越权请求
- **WHEN** 提交方提交授权范围内的任务类型，执行服务使用自己的凭证领取对应队列
- **THEN** 两者可以完成各自的操作；无凭证请求返回 401，已认证主体越权返回 403，知道队列名、任务 ID 或 worker_id 不赋予额外权限。

#### Scenario: 凭证轮换和吊销
- **WHEN** 管理员为订阅服务签发新凭证，部署切换完成后吊销旧凭证
- **THEN** 新凭证可以访问原订阅的积压任务，所有 API 实例拒绝旧凭证；查询和日志均不返回可用的 token 明文。

### Requirement: 管理操作及监控数据按资源授权

平台 SHALL 对任务管理、死信操作、队列监控和 Cron 管理统一认证，按操作及服务端确定的业务或队列范围授权。监控只读权限 SHALL 与重试及调度规则写权限独立授予。

#### Scenario: 只读运维查看和重试
- **WHEN** 只读运维查看获授权队列的积压和死信，随后尝试重试任务或批量重试死信
- **THEN** 读取成功，重试返回 403，队列和任务状态不变。没有有效凭证时，读取和写入均返回 401。

#### Scenario: 任务列表与批量操作按实际归属隔离
- **WHEN** 业务方不带过滤条件列出任务或查看监控统计，或在已授权队列的死信重试请求中夹带其他业务的任务 ID
- **THEN** 列表及统计仅覆盖其可见资源；平台在重新入队前拒绝包含越权条目的请求。

#### Scenario: 定时任务遵守目标队列授权
- **WHEN** 主体有 Cron 管理权限但尝试向无提交权限的队列创建定时任务，或一个已有规则的目标队列投递授权被撤销
- **THEN** 前者返回 403 且不创建规则；后者后续触发不会产生越权任务。列表、查看、修改、启停和删除均按规则归属校验。

#### Scenario: 指标采集与健康探针
- **WHEN** 抓取端访问部署级指标，或无凭证探针读取独立开放的最小健康端点
- **THEN** 指标仅向有部署级监控读取权限的身份返回；健康端点只返回存活状态。

### Requirement: 管理员登记持久订阅

平台 SHALL 提供开通、列出和停用订阅的管理操作，以业务范围、自定义任务类型、接收服务及步骤唯一确定订阅，以持久存储跨进程共享。授权消费队列与订阅开通应在一次管理操作内完成。

#### Scenario: 重复开通与扩容
- **WHEN** 管理员重复为服务 S 开通同一订阅，并启动该服务的三个实例
- **THEN** 服务 S 只有一条订阅，三个实例可用各自的 worker_id 直接竞争领取该服务的任务；两个需要独立收到结果的服务使用独立队列。

#### Scenario: 完成快照与停用
- **WHEN** 源任务 A 成功 ACK，此时服务 S 和 T 均已订阅，随后停用 T 的订阅
- **THEN** 按 ACK 事务确定的快照为 S 和 T 分别保留一个处理任务，同一 ACK 重放不会重复派发；停用生效后确认的新结果跳过该订阅。新增订阅从生效后的完成记录开始接收。

#### Scenario: 源任务完成时零订阅
- **WHEN** 启用派发的任务类型尚无订阅，或最后一个订阅在源任务完成前已停用
- **THEN** 平台仍允许提交和执行，成功 ACK 返回 SUCCEEDED、completion_id 和 dispatch_count=0，保存空接收方快照。相同 ACK 重放返回同一完成记录；随后开通订阅不会派发这条历史结果。

### Requirement: 通用结果 API 命名
平台 SHALL 在公开任务、投递、产物、重新执行和统计契约中使用通用任务术语，并使 OpenAPI、Python SDK 和示例与 HTTP 接口一致。

#### Scenario: 从自定义任务追溯和补跑
- **WHEN** 调用方按 task_type 提交任务，并通过 /api/v1/tasks/{task_id} 下的 deliveries 和 artifacts 资源查看结果
- **THEN** 调用方能以 source_task_id 追溯来源，通过指定投递步骤的 rerun 复用结果，或通过源任务的 rerun 重新执行。公开模型、SDK 和示例均使用上述名称。

### Requirement: 使用者定义任务类型与数据

平台 SHALL 接受使用者定义的任务类型、JSON 输入和结果摘要，并支持只携带摘要或携带产物引用。授权校验、执行和派发 SHALL 仅依赖调度字段、配置及接收方快照。

#### Scenario: 接入新类型并交付纯 JSON 结果
- **WHEN** 管理员开通自定义任务类型 document.inspect 和一个订阅，提交方用 task_type 指定该类型，执行服务 ACK 时只返回 summary 中的页数
- **THEN** 订阅服务可领取携带该摘要、空产物列表和来源标识的处理任务，接入过程无需修改调度器代码。

### Requirement: 业务输入和逐任务恢复

平台 SHALL 通过处理任务交付来源 ID、完成记录 ID、业务摘要和版本化产物引用，允许各下游组装自己的输入。下游 SHALL 在幂等业务写入成功后确认本次处理任务。

#### Scenario: 两个订阅者各取同一份产物
- **WHEN** 源任务 A 回报一份自定义摘要和一个产物引用
- **THEN** 两个服务领取不同的 task_id，但得到相同的 source_task_id=A、completion_id 和产物引用；各服务能组装各自的输入并独立 ACK。

#### Scenario: 服务停机和多实例接手
- **WHEN** 订阅服务 S 停机期间有新结果，或某实例已写入业务库但在 ACK 前退出
- **THEN** 订阅服务 T 独立继续，S 重启后可领取积压；超时任务在重试额度内以相同处理任务 ID 重新分配，幂等写入只产生一次业务效果。已 ACK 的任务不会因实例重启自动回放，重试耗尽进入死信。

### Requirement: Python Worker SDK 独立安装

项目 SHALL 提供可独立构建、安装的 Python Worker SDK。SDK SHALL 在调用方进程内通过公开 HTTP/JSON 契约执行 Worker 操作。

#### Scenario: 外部项目安装首版 SDK
- **WHEN** 外部 Python 项目在干净环境安装指定版本的 SDK wheel，配置授权凭证、队列和远程调度地址
- **THEN** 该项目可以导入 SDK、领取任务并回报结果，安装依赖无需包含调度服务端、Redis 客户端或 MySQL 驱动。

### Requirement: Worker 客户端可选续租

共用客户端 SHALL 支持固定租约和自动续租两种执行方式，按任务处理 ACK、NACK、租约代次和执行截止时间。领取、续租与回执均 SHALL 绑定服务身份、实例及当前有效执行，已接受的 ACK 重放遵循既有幂等语义。

#### Scenario: 耗时可估的任务
- **WHEN** 提交方给任务设置 20 分钟租约，执行 Worker 选择固定租约并在 15 分钟完成
- **THEN** Worker 可以直接 ACK；若它中途退出，平台按租约到期时间回收，并按重试额度重新派发或进入死信。

#### Scenario: 长任务、阻塞和旧租约
- **WHEN** 并发处理两条任务，其中一条被外部 I/O 阻塞，客户端启用自动续租
- **THEN** 客户端按任务独立续租；到达执行截止时间或失去租约时终止对应操作并停止续租。仅当前持有者可改变执行状态，其他服务即便使用相同 worker_id 也不能代为确认。

### Requirement: 管理员查看近期活跃 Worker

平台 SHALL 提供管理员只读实例列表，支持按服务和队列过滤，返回活跃窗口、实例数、实例 ID、服务、队列、最近活动时间和来源 IP。活跃状态与订阅、任务租约分别维护。

#### Scenario: 多线程与共享出口
- **WHEN** 同一服务的两个实例通过同一 NAT 出口成功 pull，其中一个以同一实例 ID 为多个线程统一领取
- **THEN** 查询返回两个实例及各自的活动时间，即使它们的 IP 相同；同一实例在多队列活跃时全局只计一次。非管理员无权列出部署地址。

#### Scenario: 活跃记录到期
- **WHEN** 实例在活跃窗口内未发起成功 pull 或任务续租
- **THEN** 实例从近期活跃列表消失，仍有效的长租约按原到期时间处理，服务订阅继续接收后续结果。
